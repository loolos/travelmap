## 1. 產品願景

一個以埃及地圖為核心的互動數位博物館。使用者點擊真實地理位置，探索當地的歷史、建築、宗教、自然地理與考古發現，並附上與地點相關的旅遊實用知識。體驗介於歷史策略遊戲的世界地圖、互動博物館與旅行指南之間。

主要用途是旅行前的知識探索，以及旅行中的現場觀察。V1.0 聚焦實際行程（埃及黑白沙漠 11 日）中的地點；行程外的重要遺址留給 V1.1。介面與內容全部使用繁體中文（zh-Hant），地點與關鍵術語附英文名稱，必要時附古埃及名稱。

### 1.1 核心原則

- **地圖優先**：地圖是首頁與常駐導航，所有內容都有地理歸屬。
- **視覺優先**：先給圖像、復原圖、剖面或動畫，再給解釋。
- **互動優先**：先讓使用者觀察、操作、預測，再揭示結論。
- **離線優先**：核心地圖、文字、關鍵圖片與互動可完整下載，斷網仍能使用。
- **證據優先**：區分確證事實、學術推測、藝術復原、AI 示意與教學模型。
- **低摩擦**：不需登入、不需通關，沒有生命值、付費或刷分機制。

### 1.2 非目標

不做即時導航、訂票、完整經營遊戲、通用百科、社群功能、線上聊天機器人。V1 不需要 3D 引擎、帳號、雲端同步、即時定位、即時匯率或價格換算。

## 2. 核心體驗與資訊架構

打開網站 → 看到埃及全境地圖 → 點擊地點 → 主圖與一句引導問題 → （若有）進入互動 → 看觀察清單與旅人手記 → 回到地圖。開啟與到訪狀態自動保存在本機。

導覽只保留四個入口：**地圖、探索日誌、離線下載、設定**。每個地點與互動都有可直接分享的連結。

### 2.1 全境地圖

地理準確、帶遊戲感的二維地圖，以尼羅河為視覺軸：淺沙色陸地、藍綠色水體、綠色河谷、小型建築圖示。不使用線上圖磚；以本地簡化 GeoJSON／SVG 繪製，真實經緯度與畫面座標分離。

- 操作：拖曳、滾輪／雙指縮放、雙擊放大、回到全境。
- 節點：顯示短名、類型圖示與探索狀態；顏色與形狀同時區分陵墓、神殿、城市、地質、水利、生態、博物館。
- 密集區（吉薩、路克索）：放大後節點自動分開；V1.0 不另繪區域詳圖。
- 篩選：只有一個「行程地點」開關，高亮本次行程所有地點。**不做逐日切換**；任何地點隨時可點。
- 地圖不是交通導航，不畫行車路線或耗時。
- 桌面：地圖約占 65–75% 寬度，右側可收合地點面板。手機：全螢幕地圖，點擊地點出現底部抽屜，可展開成全螢幕；關閉後恢復原本視角。
- 另提供可鍵盤操作的地點清單作為輔助入口。

### 2.2 地點頁（輕模板）

V1.0 所有地點使用同一個模板，由內容 JSON 驅動：

1. 返回地圖／麵包屑
2. **主圖**（必須存在 repo 中，離線可用）＋圖片類型標示（照片／復原／示意）
3. **名稱**：中文主標、英文副標；年代
4. **3 個關鍵事實**（每個 15–40 字）
5. **引導問題**（15–35 字）
6. **旗艦互動卡**（只有 5 個地點有）
7. **現場觀察清單**（3–5 項，可勾選）
8. **旅人手記**（該地點或所屬地區的 1–3 張實用卡，見第 7 節）
9. 相關地點連結
10. 可展開的資料來源與圖片出處

### 2.3 城市節點

開羅、亞斯文、路克索為城市節點，巴哈利亞綠洲與虎加達兼作城市卡，同樣使用輕模板（吉薩的今日城市說明以一段文字放在大埃及博物館頁）：主圖、40–80 字簡介、3 個事實、3–5 個「為何成為今日樣貌」的歷史轉折點。人口、經濟圖表與互動延後至 V1.1。

## 3. 視覺與內容規範

### 3.1 視覺系統

現代互動博物館加古地圖風格，不做仿古網頁。主色：沙岩 #E8D6B1、深墨 #292720、尼羅河藍 #327D91、青金石 #244C79、金色強調 #B88B43。預設淺色，可選深色。正文使用系統中文字體，標題可用系統襯線字體；不載入遠端字型。圖示風格統一，不用大量裝飾性象形文字干擾閱讀。

重要圖示不能只靠顏色表達意義；所有圖片需有 alt 與出處。

### 3.2 文字預算

| 元素 | 長度 |
|---|---|
| 地點簡介 | 40–80 字 |
| 關鍵事實 | 每則 15–40 字，共 3 則 |
| 引導問題 | 15–35 字 |
| 觀察項目 | 每項 10–30 字 |
| 互動操作說明 | 20–50 字 |
| 互動結果解釋 | 50–120 字 |
| 旅人手記卡 | 30–80 字 |
| 深入閱讀 | 預設收合 |

手機單一畫面的預設文字約 120–180 字以內（不含按鈕與使用者主動展開的內容）。這是目標，不是截斷規則。

### 3.3 內容節奏

引起好奇（問題）→ 觀察或操作 → 回饋 → 解釋原因 → 現場觀察。輕互動 30 秒–3 分鐘，旗艦互動 2–5 分鐘。不自動播放影音；答錯不阻止繼續。

### 3.4 圖片規範

- **來源**：Wikimedia Commons（優先，記錄作者與授權）＋ AI 生成示意圖。不逐館核驗博物館館藏。
- **AI 圖**：一律在圖上或圖說標示「示意」，不得當作考古證據、精確平面或真實照片。
- **儲存分級**：
  - **關鍵圖片**（每個地點的主圖、旗艦互動所需圖、城市卡主圖）：壓縮後存入 repo，納入離線核心包。
  - **非必要圖片**（延伸閱讀、補充照片）：可直接連結 Wikimedia 等線上網址；離線時顯示本地占位圖與 alt 文字，不影響頁面運作。
- 每張圖記錄：`path` 或 `url`、`alt`、`credit`、`license`、`sourceUrl`、`kind`（photo／reconstruction／illustration／ai-illustration）、`essential`（true／false）。
- 格式：WebP 為主；縮圖 20–80 KB，主圖約 100–250 KB。

### 3.5 語言與雙語標註（硬性要求）

- 所有介面、導覽、內容、互動說明、圖表標籤、提示與離線通知一律使用自然、統一的繁體中文，以台灣常見譯名為優先（例如「卡夫拉」可附「哈夫拉」作為別名供搜尋）。
- 景點、城市、博物館、法老、神祇、王朝、重要文物與專有術語提供英文名稱；首次出現時附英文，之後只用中文。
- 地圖低縮放層級只顯示中文短名；點擊後顯示完整中英文名稱。地點標題為中文主標、英文小字副標。
- 示例：吉薩金字塔群（Giza Pyramid Complex）、胡夫金字塔（Great Pyramid of Khufu）、卡納克神殿（Karnak Temple）、帝王谷（Valley of the Kings）、拉美西斯二世（Ramesses II）、荷魯斯（Horus）、象形文字（Hieroglyphs）、王名圈（Cartouche）。
- 資料模型保留 `nameZh`、`nameEn`、可選 `aliases`；搜尋支援中英文與常見異譯。HTML 設定 `lang="zh-Hant"`，英文片段標 `lang="en"`。
- 不做英文介面或簡繁切換。

## 6. 旗艦互動設計（V1.0）

### 6.1 吉薩：建造大金字塔（約 3 分鐘，ParameterLab）

問題：沒有現代機械，要怎麼組織數百萬塊石材的工程？

使用者把固定總人力分配到採石、運輸、砌築、後勤四項，並可調整年數。教學模型：每年完成量 Q = min(採石, 運輸, 砌築) × 後勤係數；後勤不足會降低可用人力。即時顯示瓶頸環節、預估完工年數與金字塔增長示意。所有生產率參數標為「遊戲假設」，與考古估計分開。不把某種坡道方案當成定論，也不把工人簡化為奴隸。結尾連到工人村、梅雷爾紙莎草（Diary of Merer）、亞斯文花崗岩。

V1.1 擴充為回合制 ResourceSim（年度推進、糧食事件、歷次嘗試比較）。

### 6.2 白沙漠：從古海洋到蘑菇石（約 2 分鐘，StepTimeline）

五個階段：海洋沉積 → 岩層形成 → 抬升出露 → 風沙差異侵蝕 → 今日地貌。拖動時間軸切換示意圖；最後一階段可切換「岩石較硬／較軟」看輪廓差異。只做定性模擬，不推算侵蝕年代。結尾為真實照片與觀察清單（質地、層理、不同高度的侵蝕形態），提醒不要敲擊或採集保護區岩石。

### 6.3 亞斯文：水壩調度（約 2 分鐘，ParameterLab）

調整上游來水、放水量與灌溉需求，看水庫儲量（流入減流出）與下游供水的變化；定性呈現發電、防洪、泥沙、農業與努比亞居民遷移的取捨。使用標註的簡化單位，不冒充真實調度資料。

### 6.4 伊斯納：操作船閘（約 1–2 分鐘，LockSim）

步驟：船進入閘室 → 關閉來水側閘門 → 調整閘室水位至目標側 → 打開目標側閘門 → 船離開。順序錯誤會解釋原因並允許重試；支援上行與下行；動畫呈現水位差。標明為教學示意。狀態機需有單元測試。

### 6.5 卡納克：千年的神殿（約 2–3 分鐘，StepTimeline）

以分期平面示意圖呈現中王國至托勒密時期歷代法老的擴建，切換時期時新增建築高亮，說明「不是一次建成」。最後一階段附大柱廳說明與現場觀察清單（方尖碑、柱頭、王名圈、聖湖）。

### 6.6 備選（時間允許才做）

若 5 個旗艦提前完成，依序考慮：伊斯納 LockSim 的下行動畫細節、大埃及博物館「認識王名圈」小互動、三座金字塔高度比較。其他原 V1.4 互動設計（阿布辛貝搬遷、孔翁波雙神殿、艾德夫神話、帝王谷尋找圖坦卡門、紅海板塊與珊瑚、中世紀開羅古今地圖、代赫舒爾坡度實驗）保留為 V1.1 設計，見附錄 A。

## 9. 離線優先架構（V1.0 必要）

### 9.1 使用者體驗

- 第一次需連網開啟。地圖與介面先載入，核心包在背景下載。
- 「離線下載」頁顯示：進度（已快取大小／總大小）、未完成項目、失敗重試按鈕、「下載全部核心內容」按鈕。
- 「離線就緒」只在**清單中所有必要資源都已確認在快取中**時才顯示；不因頁面能開就宣稱可離線。
- 非必要的線上圖片不計入離線就緒；離線時顯示占位圖。
- 提供 iPhone「加入主畫面」說明與「出發前請用飛行模式實測」提示。說明瀏覽器可能清除快取（尤其 iOS、私密模式、儲存空間不足）。
- 支援時呼叫 `navigator.storage.persist()`，但不保證取得。

### 9.2 資源分包與預算

V1.0 只有兩層：

| 包 | 內容 | 預算 |
|---|---|---|
| App Shell | HTML、CSS、JS、地圖資料、圖示、離線頁 | 2–5 MB |
| Core | 全部地點 JSON、關鍵圖片、互動資源 | 目標 ≤ 40 MB，上限 60 MB |

非必要圖片不打包。可選擴充包、高清包、多包管理延後至 V1.1。建置腳本實際統計位元組並輸出體積報告。

### 9.3 Service Worker

使用 Vite + vite-plugin-pwa（Workbox injectManifest）自訂 SW。建置時產生離線清單（URL、位元組、版本、hash、`essential`）。

- **Install**：預快取 App Shell；失敗則不啟用新版。
- **Download**：頁面送指令給 SW，SW 分批（限制併發）抓取 Core 清單並寫入 Cache Storage，以 postMessage 回報進度；中斷後依清單補齊。
- **Fetch**：同源版本化資源 cache-first；導覽請求回退到已快取的 shell（限制在 repo scope 內）；線上圖片走 network-first，失敗時回占位圖。
- **Verify**：逐項檢查清單中必要資源是否在快取中；進入離線頁時重新檢查，不只相信舊的完成標記。
- **Update**：有新版時提示使用者重新整理；不自動 skipWaiting。旅行期間不推送大版本。
- 快取與資料庫名稱加上專案命名空間，不影響同網域其他 GitHub Pages 專案。

V1.1 再加入：多包、可選包刪除、v1 → v2 更新中斷保護的完整測試。

### 9.4 儲存分工

Cache Storage：HTML／JS／CSS、JSON、地圖與圖片。IndexedDB（idb-keyval）：探索狀態、觀察勾選、筆記、設定。使用者進度與快取版本分離，更新網站不會遺失筆記。

### 9.5 離線失敗處理

缺圖顯示本地占位與 alt；必要圖片缺失時不得顯示「離線就緒」。不載入 Google Fonts、CDN JS、線上圖磚或 API 來支撐核心功能（非必要圖片除外）。

## 10. 技術架構

React + TypeScript + Vite；CSS Modules；SVG 地圖配合 d3-geo／d3-zoom；idb-keyval；vite-plugin-pwa（Workbox）。少依賴、純靜態、無後端、無 API key。

使用 HashRouter，避免 GitHub Pages 深層連結 404：`/#/map`、`/#/place/giza-khufu`、`/#/place/giza-khufu/pyramid-build`、`/#/offline`、`/#/journal`。Vite `base` 設為 `/travelmap/`；manifest 的 `start_url`、`scope` 與 SW 註冊都限定在此子路徑；資源路徑由 `BASE_URL` 產生，不硬編碼 `/assets/...`。

## 11. 部署與開發規範
